## 5. Recommended primary implementation

**Proposed primary physical carrier:** acquire one traceable recoverable specimen with fixed geometry and free lateral surfaces; none is currently identified. **Primary robot operation:** constrained recontact and pressing/holding after a reproducible loading/recovery history, with approach, retreat/reposition, recontact, target attainment, hold, and final withdrawal. This preserves the current fast/slow hidden-state question and requires only one arm with a rigid tool. A lateral traverse or a second object can later test a declared transfer axis. Grasp–transport should wait for verified per-jaw force/current observability and a demonstrated decision gap.

**Small priority request package, not yet submitted:** one working FR3/Panda configuration selected with the lab operator; one rigid rounded tool or platen with a fixed sample holder; one calibrated Bota/Robotiq F/T mounted in the load path; one D435 RGB/side view or another calibrated side camera. Request the installed controller/API configuration and a sample synchronized log alongside these four components. OptiTrack is optional for independent tool/base validation. This package avoids adding a grasping hand, multiple cameras, or a materials-test machine before the core information question is established. The user's request pathway makes it a credible proposal; no named device has been allocated or verified for NR.

**Implementation sequence:**

1. Reuse archived 1D data/code to define units, timestamps, action semantics, and strong classical controls. Keep its claim level unchanged.
2. Build the required spatial 2D mechanism with measured lateral observations and verified contact/material laws. Add a deployable observation model before fitting representations.
3. Choose the 3D arm asset only after the actual robot/controller configuration is identified. Couple its full joint dynamics to a qualified 3D hidden-mechanism plant, with reaction wrenches feeding back to the arm and common causal sensing. MuJoCo plus SOFA/SofaViscoElastic is a candidate integration trial, not an already operational platform.
4. Run one complete task and the minimal estimator comparison before a large neural baseline sweep. Only after a useful, identifiable state effect survives common feedback should a second task/carrier broaden the claim.
5. Collect material-bench calibration early if feasible. Perform physical robot operation only after the required 3D robot simulation evidence is complete.

Reusable pieces: current synthetic generators and classical estimation code; lab session/metadata/calibration templates; the lab's working controller interface and robot description; standard camera/FT drivers once matched to actual devices. New pieces: carrier/contact solver qualification, observation/actuation timing adapter, bidirectional coupling, physically replayed history generation, online estimator-state interface, complete-task evaluator, and grouped result aggregation.

## 6. Resource-limited alternative

Use the existing workstation for the 2D mechanism and a small, fully articulated 3D simulation with a reduced but independently verified spring–dashpot carrier and rigid contact geometry. Preserve dynamic internal variables, realistic joint limits/actuator behavior, two-way forces, and measured/planned sensor timing. This avoids deploying a high-resolution continuum or image-learning stack before the state question is resolved. The limited model supports claims about that specified carrier; it cannot establish arbitrary deformable geometry or actual foam fidelity.

For early physical calibration, request a bench-mounted F/T or load cell with a suitable loading stage and side camera if available through the lab. Device configuration records can be obtained earlier, but physical arm manipulation waits for the S3 simulation gate. A stage is a bench substitute only. It cannot replace the user's mandatory full-arm simulation stage or be labeled a completed robot manipulation demonstration. A cheaper carrier/platform changes the evidence scope; it does not change the general hidden-object-state theme.

2. **Physical carrier, confirmed absent:** select and obtain one traceable sample, specify/build its minimal rigid loading fixture, and then collect a small load–hold–release calibration record demonstrating reversible memory above measurement uncertainty. 3. **Deployment configuration record, obtainable through the confirmed request path:** record the chosen arm, installed controller/API/firmware, permissible command interface, and sensor mounting. This is a short equipment configuration sheet, not another generic permission question.

Offline formalization, code audit, data splitting, and mechanism experiments can proceed while these records are obtained. Do not freeze a hardware-specific simulation latency, force threshold, or camera mode before the evidence arrives.
